# Smee Obsidian Vault — Hermes Operating Rules

## Core Behavior
- **Priority-first**: Always check `10-Projects/` and `20-Areas/` before creating new notes
- **Flat-file convention in 10-Projects/**: Use flat filenames (e.g., `Hoang-Ninh-Ecolife.md`), NOT nested subdirs unless existing project has subdir convention
- **Protocol Section compliance**: Always verify frontmatter fields: `slug`, `category`, `status`, `type`. Add defaults if missing per vault-maintenance skill.
- **Wikilink discipline**: Use `[[Note Name]]` syntax for all internal references. Never use bare URLs in note content unless they're external citations.

## Vietnamese Context (VN Typing Guardian)
- All conversational output to user: pure Vietnamese, no Chinese characters mixed in
- When processing VN input from user: auto-check for common typos (teengalicious style) via vietnamese-nlp skill
- Internal thinking can be Sino-Vietnamese if needed, but final output must be clean Vietnamese
- Preserve proper tone marks (dấu đúng) on all Vietnamese text

## Obsidian Vault Structure
```
00-Meta/           → Protocol, configuration, indices
10-Projects/       → Active projects (flat files)
20-Areas/          → Ongoing areas of responsibility
30-Inbox/Suggestions → Low-priority ideas waiting for processing
40-Knowledge-Synthesis → Curated knowledge and frameworks
50-Archive/        → Completed project notes
60-Backups/        → Vault backup copies
70-Templates/      → Reusable templates (one file per template = one folder)
80-Scripts/        → Automation scripts (Python, JavaScript)
90-Inbox/          → Unsorted capture point
A1-Pending Inbox/  → Waiting for processing
A2-Smee/           → Smecology content, notes
```

## Workflow Rules
### Creating Notes
1. Pick section based on content type — if uncertain, use `30-Inbox/Suggestions/` or `90-Inbox/` first
2. Use proper frontmatter with all required fields
3. Add wikilinks to at least 2 related notes
4. Set status field from available options

### Updating Notes
1. Search first before editing — avoid duplicates
2. Never rewrite entire note unless restructuring — prefer `patch` for targeted edits
3. Update MOCs (index notes) within 24h of creating child notes per obsidian skill requirements
4. Run `vault-audit` patterns if structural changes span multiple files

### Searching Notes
1. Prefer `search_files` over bash tools for reliability on Windows
2. When finding content, follow wikilinks to discover related context (chain search up to 3 levels)
3. Check session_search first before vault file scanning — conversation memory is faster than disk I/O

## Memory & Context Persistence
- Save recurring patterns as skills when they occur 3+ times in same week
- Update `00-Meta/` files only via agent workflow (not manual editing)
- Cross-reference between notes: every "how-to" note should link to relevant "reference" and "template" notes

## Agent Permissions
- Auto-approve: file reads, small edits under 50 lines, creating new template instances
- Manual confirm: batch operations (10+ files), vault restructuring, deleting archived notes
- Always show diff before writing to existing production notes in `A2-Smecology/`

## Error Handling
- If obsidian skill returns incomplete content, load the specific file directly via read_file
- For encoding issues on Windows: always use utf-8-sig when reading/writing markdown files
- If vault drift detected (missing frontmatter fields), run batch fix using patterns from `vault-maintenance` skill
